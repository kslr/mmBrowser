# i18n 规格（简体中文 + 英文）

> 注：项目后来从 SwiftPM 换成了 Xcode 工程，本文中关于 SwiftPM 资源包（`Bundle.module`、`mmBrowser_*.bundle`）、`scripts/build-app.sh` 和 `.build/debug` 的描述已过时。翻译也已从 `.strings`/`.stringsdict` 换成 String Catalog（`.xcstrings`），现行做法以 README 的「本地化」一节为准。

## 目标

mmBrowser 现在所有界面、错误信息、命令行输出都是硬编码中文。改成支持 **简体中文（zh-Hans）+ 英文（en）**，**跟随系统语言**（含 macOS「系统设置 > 通用 > 语言与地区」里给单个 App 选语言），不加 App 内的语言设置。覆盖范围：MMApp 界面、MMCore 的错误信息和用户可见文字、mmctl 命令行（帮助、输出、报错）。

## 约束

- 只能在 macOS 编译。在仓库根目录跑 `~/macvm/tools/macbuild`（同步到 VM 并执行 `swift build && swift test`，也可传命令：`~/macvm/tools/macbuild ./scripts/build-app.sh`）。VM 只有 CLT + swift.org Swift 6.4.2，**没有 Xcode → 不能用 `.xcstrings`**，用 `.strings`（必要时 `.stringsdict`）。
- 开发时直接跑 `.build/debug/mmctl`、`swift run`；发布时由 `scripts/build-app.sh` 手工拼 `.app`。两种场景都必须能找到翻译。

## 资源与查找

- `Package.swift`：加 `defaultLocalization: "en"`；MMCore、MMApp、mmctl 三个 target 各加 `resources: [.process("Resources")]`。
- 文件位置：`Sources/<Target>/Resources/{en,zh-Hans}.lproj/Localizable.strings`。英文里需要单复数的计数文案，用 `en.lproj/Localizable.stringsdict`（中文不需要）。也可以改写措辞避开复数（如 "Profiles: 3"），优先这样。
- `Sources/MMCore/L10n.swift`：

  ```swift
  public enum L10n {
      /// 打包后的 .app 里资源包在 Contents/Resources（App 和 Contents/MacOS/mmctl 都按可执行文件位置推算）；
      /// 找不到就用 SwiftPM 生成的 Bundle.module（开发时的 .build 目录）。
      public static func resourceBundle(_ name: String, dev: () -> Bundle) -> Bundle
  }
  ```

  推算方式：`Bundle.main.executableURL` 的上两级目录 + `Resources/<name>.bundle`，存在就用，否则 `dev()`。不要再加别的查找路径。

- 每个 target 各有一个**内部**函数（MMCore 在 `L10n.swift`，MMApp 在 `Sources/MMApp/L10n.swift`，mmctl 在 `Sources/mmctl/L10n.swift`）：

  ```swift
  private let bundle = L10n.resourceBundle("mmBrowser_MMCore") { .module }   // 按模块改名
  func L(_ key: String.LocalizationValue) -> String { String(localized: key, bundle: bundle) }
  ```

  资源包名是 SwiftPM 生成的 `<包名>_<target名>`，即 `mmBrowser_MMCore`、`mmBrowser_MMApp`、`mmBrowser_mmctl`，以实际 `.build` 里的为准。

## 调用规则

- 所有用户可见文字都走 `L(...)`。SwiftUI 里统一传 String：`Text(L("..."))`、`Button(L("..."))`、`Label(L("..."), systemImage:)`、`TableColumn(L("..."))`、`.help(L("..."))`、`.navigationTitle(L("..."))` 等（大多数 SwiftUI 构造器没有 bundle 参数）。
- 插值：`L("alert.launchFailed \(name)")` 生成的 key 是 `alert.launchFailed %@`。String → `%@`，Int → `%lld`，Double → `%lf`。`.strings` 里的 key 必须和生成的一字不差；译文里可以用 `%1$@`、`%2$lld` 调整参数顺序。
- 已经格式化好的东西（日期 `.formatted()`、IP、名称）当 String 参数插进去。
- key 命名：`<区域>.<项>[.<子项>]`，小写驼峰，点分隔。例：`common.cancel`、`common.listSeparator`、`list.column.name`、`list.empty.trash`、`editor.proxy.title`、`alert.launchFailed`、`error.proxy.authFailed`、`csv.header.name`、`cli.create.help.proxy`。同一模块内重复出现的通用词放 `common.*`。
- 每个 `.strings` 文件按区域分组，组前一行注释（`/* 列表 */`），组内按 key 排序。en 和 zh-Hans 的 key 集合必须完全一致，占位符（个数、类型）必须一致。
- 中文译文就是现在代码里的原文，不要改写。英文译文简洁、符合 macOS 习惯（标题用 Title Case，按钮短）。

## 不是单纯替换字符串的地方

- `Sources/MMApp/AppModel.swift:114` `setupError?.hasPrefix("找不到 Google Chrome")`：不要再比较文案，改成按错误类型或单独的状态判断。
- 默认环境名 `"环境-\(seq)"`（AppModel 342–352 附近）和复制环境的 `"\(src.name) 副本"`（`Sources/MMCore/Store/Store.swift:296`）：按当前语言生成，已有数据不动。`Sources/MMApp/SnapshotRunner.swift:156` 依赖这个后缀，要跟着改（用 duplicate 的返回值或同一个 L 结果，不要写死中文）。
- 标签拼接的 `"、"`：改成 `common.listSeparator`（zh `、`，en `, `）。
- CSV（`Sources/MMCore/Import/ProfileCSV.swift`）：
  - 导出：表头和取值（是/禁止/询问 等）按当前语言。英文表头用 `rawValue`（导入本来就认）。
  - 导入：**继续同时认中文和英文**表头与取值。现在 `aliases` 用 `title.lowercased()`，title 本地化后会变——要把中文表头单独保留为固定别名（字面量），取值别名（`"是"`、`"禁止"`、`"询问"`、`"直连"`、`"自动"`）同样保留字面量。
- `ImportError` 等错误的关联值（`missingColumn`、`badLine` 的说明）改为本地化后的文字。
- mmctl：`CommandConfiguration` 的 abstract/discussion、`@Option/@Flag/@Argument(help:)`、`print` 输出、`ValidationError`/抛出的错误都走 `L`。ArgumentParser 自带的 USAGE/OPTIONS/`--help` 说明保持英文。

## 不动

- 代码注释、测试的 `@Suite`/`@Test` 名称。
- `SnapshotRunner` 里的演示数据（`seedDemoData` 等写进库里的名字、备注），只本地化它输出给人看的报错。
- 数据库里已有的数据、数据库列名、发给 Chrome 的参数。

## 测试与检查

- 现有测试里写死中文期望值的（如 `Tests/MMCoreTests/ImportTests.swift:67-68`、`:92`）改成用 `L(...)`（`@testable import MMCore`）算期望值，保证在任何系统语言下都通过。
- 新增一个测试：三个 target 的 en 与 zh-Hans `Localizable.strings` 的 key 集合一致、每个 key 的占位符一致（读源码目录里的 `.strings` 文件即可，用 `PropertyListSerialization` 或 `NSDictionary(contentsOf:)` 解析）。
- 新增 `scripts/check-l10n.py`（纯标准库 Python 3，Linux 上能跑，`python3 scripts/check-l10n.py`）：
  1. 列出 `Sources/` 下剩余的含中文的字符串字面量（跳过 `//`、`///`、`/* */` 注释），带 文件:行号；
  2. 列出代码里 `L("...")` 用到、但对应 target 的 `.strings` 里没有的 key（插值部分按上面的规则推断不了类型时，只比对插值前的前缀即可）；
  3. 列出 en/zh-Hans key 不一致的条目。
  有 2、3 类问题时退出码非 0。第 1 类只报告（CSV 导入别名、演示数据是允许的）。

## 打包（`scripts/build-app.sh`）

- 把 `.build/release/mmBrowser_{MMCore,MMApp,mmctl}.bundle` 拷到 `Contents/Resources/`。
- 主 bundle 建 `Contents/Resources/en.lproj/InfoPlist.strings`、`zh-Hans.lproj/InfoPlist.strings`（内容可只有 `CFBundleDisplayName`），Info.plist 加 `CFBundleDevelopmentRegion` = `en`、`CFBundleLocalizations` = `[en, zh-Hans]`。这样系统菜单（退出/隐藏/编辑等）跟着语言走，系统设置里能单独给 App 选语言。
- `codesign --force --deep --sign -` 必须仍然成功。如果 SwiftPM 的资源包让 codesign 报错，再改方案（比如只拷 `.lproj`），并在汇报里说明。

## 验收命令

- `~/macvm/tools/macbuild` 全部通过。
- `python3 scripts/check-l10n.py` 退出码 0。
- mmctl 切语言：ArgumentParser 不认 `-AppleLanguages` 参数，用 tool 自己的 defaults 域：`defaults write mmctl AppleLanguages '(en)'` 后跑 `.build/debug/mmctl --help`、`mmctl create --help`、一个会报错的命令；再换 `'(zh-Hans)'` 跑一遍；最后 `defaults delete mmctl AppleLanguages` 还原。不要改 VM 的全局语言。
- App 截图：`MMBROWSER_HOME=$(mktemp -d) .build/debug/mmBrowser --snapshot <目录> -AppleLanguages '(en)'`（App 认这个参数）。
